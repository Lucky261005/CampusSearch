# CampusSearch

Search and question answering over public CHRIST (Deemed to be University) information, running locally.

- **Keyword search**: a custom inverted index with BM25 (no search library).
- **Semantic search**: `all-MiniLM-L6-v2` embeddings stored in PostgreSQL with pgvector.
- **Hybrid search**: the two rankings merged with Reciprocal Rank Fusion.
- **Ask AI**: answers generated by Groq from retrieved passages, with citations checked against the stored
  source text. Without a Groq key it shows the retrieved passages instead.

Every document carries a provenance label:

| Provenance | Meaning |
|---|---|
| `official_web` | Fetched from an official `christuniversity.in` URL |
| `supplied_document` | A file supplied locally whose official URL could not be verified |
| `illustrative` | A synthetic sample record written for this project. **Not official information** |

This is a student project and not an official CHRIST University service.

## Requirements

Windows, macOS or Linux with Python 3.13, Node.js 22, and Docker. The commands below use the Windows venv
path `backend/.venv/Scripts/python`; on macOS/Linux use `backend/.venv/bin/python`.

## Setup

```bash
docker compose up -d db
```

```bash
cd backend
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m pip install -r requirements-ml.txt
```

The second install (CPU PyTorch and Sentence Transformers, about 1 GB) is only needed for semantic and hybrid
search. Without it, keyword search and Ask AI's keyword fallback still work, and semantic search reports
that it is unavailable.

```bash
cd frontend
npm install
```

## Load documents

From `backend/`:

```bash
.venv/Scripts/python -m app.ingest --manifest data/sources.json --prune --reindex
```

- **`--manifest data/sources.json`** fetches the official pages and PDFs listed there, one request per second.
  `data/SOURCES.md` explains what is included and which sources were rejected, and why.
- **`--prune`** deletes official documents that are no longer listed in the manifest.
- **`--reindex`** chunks and embeds the documents. PDF chunks keep their page numbers.

Optional:

```bash
.venv/Scripts/python -m app.ingest data/seed_documents.json
```

This loads the 12 illustrative sample records used by the v1 benchmark. They are labelled as not official
in the API and the UI.

```bash
.venv/Scripts/python -m app.ingest --zip "path/to/Scholarship Notice.zip" --collection scholarship-notices --category scholarships --reindex
```

This loads PDFs from a local ZIP. The ZIP is read in memory and nothing is extracted to disk. Unsafe paths,
symbolic links, non-PDF files and oversized entries are rejected.

### Refreshing and removing documents

Re-running the manifest command is safe:

| Situation | Result |
|---|---|
| Content unchanged | `unchanged`; embeddings are reused |
| Only the title or metadata changed | `metadata_updated`; chunks are kept |
| Content changed | `updated`; the old chunks are removed in the same transaction, so stale text is never searchable, and `--reindex` embeds the new text |
| Same content at a different URL | `duplicate`; not stored again |

```bash
.venv/Scripts/python -m app.ingest --delete "https://christuniversity.in/some-page"
```

This removes one document and its chunks.

**Restart the backend after ingesting.** The keyword index is built when the backend starts.

### Extraction failures

Ingestion refuses documents rather than storing empty or misleading text:

- PDFs with no text layer (scans) fail with "probably scanned or image-based (OCR is not supported)".
- Poster PDFs whose only text is boilerplate shared with the rest of a ZIP are rejected.
- Unreachable URLs and unsupported content types are reported as `skip:` lines.
- PDFs where some pages have little text are stored with `extraction_status = 'warnings'` and a note.

## Run

```bash
cd backend
.venv/Scripts/python -m uvicorn app.main:app --port 8000
```

```bash
cd frontend
npm run dev
```

Open http://localhost:5173. The Vite dev server forwards `/api` to the backend.

### Optional: Groq answers

Create a key in the Groq console and set it **only in your own terminal**, never in code, chat or a
committed file. In PowerShell, before starting the backend:

```powershell
$env:GROQ_API_KEY = Read-Host "Groq API key" -AsSecureString | ConvertFrom-SecureString -AsPlainText
```

This requires PowerShell 7. In Windows PowerShell 5.1, use `$env:GROQ_API_KEY = "<your key>"` in your own
session. The backend reads the key from the environment only; it does not load `.env` files.

## Tests and evaluation

From `backend/`:

```bash
.venv/Scripts/python -m pytest -q
```

From `frontend/`:

```bash
npm test
```

From the repository root:

```bash
backend/.venv/Scripts/python -m pytest -q evaluation
```

```bash
backend/.venv/Scripts/python -m evaluation.run --benchmark v2
```

`evaluation/RESULTS.md` is the original v1 baseline, measured on 12 illustrative records and one official
page. `evaluation/RESULTS_v2.md` is the official-corpus benchmark. The runner refuses to overwrite saved
results that were measured on a different corpus. Read the caveats in both reports before quoting any
number.
