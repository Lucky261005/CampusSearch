# CampusSearch

Search and question answering over public CHRIST (Deemed to be University) information, running on your
own computer.

- **Keyword search**: a custom inverted index with BM25 (no search library).
- **Semantic search**: `all-MiniLM-L6-v2` embeddings stored in PostgreSQL with pgvector.
- **Hybrid search**: the two rankings merged with Reciprocal Rank Fusion.
- **Ask AI** (optional): answers generated by Groq from retrieved passages, with citations checked against
  the stored source text. Without a Groq key it shows the retrieved passages instead.

> **This repository is source code, not a hosted service.** There is no public CampusSearch website or
> shared AI backend. You run everything locally, and AI answers, if you enable them, use **your own** free
> Groq key. This is a student project and not an official CHRIST University service.

Every document carries a provenance label:

| Provenance | Meaning |
|---|---|
| `official_web` | Fetched from an official `christuniversity.in` URL |
| `supplied_document` | A file supplied locally whose official URL could not be verified |
| `illustrative` | A synthetic sample record written for this project. **Not official information** |

**Corpus policy.** Illustrative records are excluded from search and Ask AI by default. They are only
returned when a request opts in explicitly, through the UI checkbox "Include illustrative sample records",
`include_illustrative=true` on `/api/search`, or `"include_illustrative": true` in `/api/ask` filters. Tests
and the v1 benchmark opt in because their fixtures are illustrative.

## Cost: ₹0 by design

Everything needed to run CampusSearch is free and local:

- PostgreSQL with pgvector, in Docker. Docker Desktop is free for personal and educational use.
- The `all-MiniLM-L6-v2` embedding model on your CPU. It is a free download of about 90 MB on first use.
- Keyword, semantic and hybrid search.
- Optional OCR (RapidOCR) on your CPU.

There is no hosting, no paid API and no subscription. **Basic search needs no API key at all.**

**Groq is the only external service, and it is optional.** Without a key, everything except AI-written
answers works, and Ask AI shows the retrieved passages instead. If you add a key:

- Use your own **free-plan** Groq account with no payment method. A configured key does not by itself mean
  requests are free. Groq's public docs do not state free-plan limits for every model, so check your plan
  at https://console.groq.com/settings/limits and https://console.groq.com/settings/billing. The provider's
  current free-tier limits always apply on top of the local limits below.
- The app never switches to another provider or model, and never retries a rate-limit (HTTP 429) or
  account-blocked response.

### Local AI limits

Each installation enforces conservative limits **before** any request reaches Groq:

| Limit | Default | Setting (non-secret environment variable) |
|---|---:|---|
| AI requests per local calendar day | 10 | `CAMPUSSEARCH_AI_DAILY_LIMIT` |
| AI requests per rolling minute | 3 | `CAMPUSSEARCH_AI_PER_MINUTE_LIMIT` |
| Generated tokens per answer | 600 | `CAMPUSSEARCH_AI_MAX_TOKENS` |

- The daily count is stored in your local database (table `ai_usage`), so it survives backend restarts. It
  resets at local midnight.
- Updates are atomic, so simultaneous questions cannot get past a limit.
- **What counts:** every request that was sent to Groq, whatever the result: an answer, an HTTP error, a
  429, or a timeout after sending (Groq may have received it).
- **What does not count:** questions that never reach Groq. That means no key set, an active cooldown, a
  local limit already reached, or a connection that could not be made.
- A retry after a timeout or a Groq 5xx error is a second request and needs a free slot.
- **After a 429** the app sends nothing until Groq's `retry-after` time has passed (60 s if none is given,
  capped at 10 minutes).
- If the usage table cannot be reached, no AI request is sent at all.

Each Ask response reports `llm_called` (whether a request was actually sent) and `llm_model`.

## Quick start on Windows

You need **Git**, **Python 3.13**, **Node.js 22** and **Docker Desktop**, all free. Run these commands in
PowerShell. Steps 4 and 5 download about 1 GB of Python packages and fetch public pages from
`christuniversity.in`.

**1. Get the code**

```powershell
git clone <repository-url> CampusSearch
cd CampusSearch
```

**2. Start the database** (Docker Desktop must be running)

```powershell
docker compose up -d db
```

**3. Install the backend**

```powershell
cd backend
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m pip install -r requirements-ml.txt
```

The second install (CPU PyTorch and Sentence Transformers, about 1 GB) is only needed for semantic and
hybrid search. Without it, keyword search and the Ask AI fallback still work, and semantic search reports
that it is unavailable.

**4. Load the official documents and build the search index** (still in `backend`)

```powershell
.venv\Scripts\python -m app.ingest --manifest data/sources.json --prune --reindex
```

This takes a few minutes. It fetches the sources listed in `data/sources.json`, one request per second, and
embeds them. The first run downloads the embedding model.

**5. Start the backend** (leave this window open)

```powershell
.venv\Scripts\python -m uvicorn app.main:app --port 8000
```

**6. Start the frontend** (in a second PowerShell window)

```powershell
cd CampusSearch\frontend
npm install
npm run dev
```

**7. Open http://localhost:5173**

The frontend forwards `/api` requests to the backend on port 8000. Search works immediately. Ask AI shows
retrieved passages until you add a Groq key.

### Optional: AI answers with your own Groq key

1. Create a free account and an API key at https://console.groq.com. Do not add a payment method.
2. Set the key **only in the PowerShell window that runs the backend**. Never put it in code, in a
   committed file, in the frontend, or in a chat. In PowerShell 7:

   ```powershell
   $env:GROQ_API_KEY = Read-Host "Groq API key" -AsSecureString | ConvertFrom-SecureString -AsPlainText
   ```

   In Windows PowerShell 5.1, use `$env:GROQ_API_KEY = "<your key>"`. The variable lasts only for that
   window.
3. Start the backend in that same window (step 5). A backend started from another window will not see
   the key.

The backend reads the key from its environment only. It does not load `.env` files, the key never reaches
the browser, and errors and logs never include it.

**Model.** The default is `openai/gpt-oss-120b`, called with `reasoning_effort: "low"` and JSON output. The
earlier default, `llama-3.3-70b-versatile`, was shut down for developer-tier keys on 2026-08-16 according to
Groq's deprecations page. To use a different model, set `$env:GROQ_MODEL = "<model id>"` before starting the
backend. Check https://console.groq.com/docs/models first, because models are retired regularly. The app
never chooses a different model on its own.

## Troubleshooting

| What you see | Cause | What to do |
|---|---|---|
| Ask AI: "answer generation is not configured (GROQ_API_KEY unset)" | The backend has no key. This is normal without AI. | Optional: set your key in the backend's window and restart the backend. |
| "the answer service rejected the API key; check GROQ_API_KEY" | Wrong, expired or revoked key | Create a new key in the Groq console and set it again. |
| "the configured model '…' is not available; set GROQ_MODEL" | The model was retired or is not on your plan | Pick a current model from Groq's models page and set `GROQ_MODEL`. |
| "rate limit or quota was reached; AI answers are paused for about N s" | Groq's free-tier limit (HTTP 429) | Wait. Nothing is sent until the pause ends. Search keeps working. |
| "account has reached its usage or spending limit" | Groq blocked the account | Check your Groq console. CampusSearch will not work around it. |
| "this installation's AI limit of 3 requests per minute has been reached" | The local per-minute limit | Wait the number of seconds shown. |
| "this installation's daily AI limit (10 requests) has been reached" | The local daily limit | It resets at local midnight. To change it, set `CAMPUSSEARCH_AI_DAILY_LIMIT` before starting the backend. |
| "the local AI usage counter is unavailable" | The database is not reachable | Start it with `docker compose up -d db`. AI stays off until the counter works. |
| "semantic search unavailable: embedding model not loaded" | `requirements-ml.txt` not installed, or the model could not be downloaded | Install it and run step 4 once with internet access. Keyword search works meanwhile. |
| "cannot connect to PostgreSQL" during ingestion | The database container is not running | `docker compose up -d db` |
| `npm run dev -- --port …` starts but the page 404s | PowerShell drops `--` when passing it through npm | Use plain `npm run dev`, or `npx vite --port 5173`. |
| New documents are not found by keyword search | The keyword index is built when the backend starts | Restart the backend after ingesting. |

## More about documents

From `backend/`. Optional extras:

```powershell
.venv\Scripts\python -m app.ingest data/seed_documents.json
```

This loads the 12 illustrative sample records used by the v1 benchmark. They are hidden from normal
searches.

```powershell
.venv\Scripts\python -m app.ingest --zip "path\to\notices.zip" --collection scholarship-notices --category scholarships --reindex
```

This loads PDFs from a local ZIP. The ZIP is read in memory and nothing is extracted to disk. Unsafe paths,
symbolic links, non-PDF files and oversized entries are rejected. The documents are labelled
`supplied_document`.

### Refreshing and removing documents

Re-running the manifest command is safe:

| Situation | Result |
|---|---|
| Content unchanged | `unchanged`; embeddings are reused |
| Only the title or metadata changed | `metadata_updated`; chunks are kept |
| Content changed | `updated`; the old chunks are removed in the same transaction, so stale text is never searchable, and `--reindex` embeds the new text |
| Same content at a different URL | `duplicate`; not stored again |

```powershell
.venv\Scripts\python -m app.ingest --delete "https://christuniversity.in/some-page"
```

This removes one document and its chunks. `--prune` with `--manifest` deletes official documents that are no
longer listed. `data/SOURCES.md` lists what is included, and which sources were rejected and why.

### Optional: OCR for scanned PDFs

Six official PDFs are scans with no text layer. They are marked `"ocr": true` in `data/sources.json` and are
skipped unless you enable OCR. OCR runs locally on the CPU, needs no system packages, and takes about
280 MB and roughly 10 seconds per page.

```powershell
.venv\Scripts\python -m pip install -r requirements-ocr.txt
.venv\Scripts\python -m app.ingest --manifest data/sources.json --prune --ocr --reindex
```

OCR output is stored with `extraction_status = 'warnings'` and a note giving the mean recognition confidence.
A document is rejected if OCR yields fewer than 200 characters or a mean confidence below 0.75. OCR text can
contain recognition errors.

### Extraction failures

Ingestion refuses documents rather than storing empty or misleading text:

- PDFs with no text layer (scans) fail with "probably scanned or image-based (ingest with --ocr if OCR is
  installed)".
- If plain extraction runs words together on a page, layout extraction is used for that page instead, but
  only when it has fewer run-together words and keeps at least 95% of the text. Otherwise the plain text is
  kept and the page is listed in `extraction_note` as needing manual inspection.
- Poster PDFs whose only text is boilerplate shared with the rest of a ZIP are rejected.
- Unreachable URLs and unsupported content types are reported as `skip:` lines.

## Tests and evaluation

None of these commands make Groq requests.

```powershell
cd backend
.venv\Scripts\python -m pytest -q
```

```powershell
cd frontend
npm test
npm run build
npm run lint
```

From the repository root:

```powershell
backend\.venv\Scripts\python -m pytest -q evaluation
backend\.venv\Scripts\python -m evaluation.run --benchmark v2-6b --overwrite
```

There are three saved benchmarks:

- `evaluation/RESULTS.md` (v1) is the original baseline, measured on 12 illustrative records and one
  official page.
- `evaluation/RESULTS_v2.md` (v2) is the first official-corpus benchmark.
- `evaluation/RESULTS_v2_6b.md` (v2-6b) uses the same questions after the retrieval improvements.

v1 and v2 are frozen and refuse to run again. v2-6b is only replaced when `--overwrite` is passed. Read the
caveats in each report before quoting any number. Two retrieval cases are known failures, marked as expected
failures in `evaluation/test_passages_v2.py`.

### Checking real AI answers (uses your Groq allowance)

With a keyed backend running, from the repository root:

```powershell
backend\.venv\Scripts\python -m evaluation.groq_ask_check --live
```

Without `--live` the script only explains what it would do, and sends nothing. With `--live` it asks six
fixed questions through `/api/ask`: one source, several sources, an unanswerable question, an unsupported
date, and the illustrative policy with and without opt-in. That is at most six Groq requests, all within the
local limits. It stops at the first limit response.

The answers are written to `evaluation/private/groq_ask_log.json`, which is gitignored. Judge them with
`evaluation/MANUAL_REVIEW.md`; passing citation checks does not mean an answer is correct.

`evaluation.run --groq` would make one request per benchmark question (up to 26). It also obeys the local
limits and stops at the first limit, so run it only deliberately.
